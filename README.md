# PyTorch Deep Learning DDP

EMNIST image classification with PyTorch. The project supports single-GPU training, multi-GPU Distributed Data Parallel (DDP) training, labeled inference, checkpointing, metrics, and visualization.

## Features

- EMNIST dataset loading with configurable splits and augmentation.
- CNN image classifier implemented with PyTorch.
- Single-process training on CPU, MPS, or one CUDA device.
- Multi-GPU DDP training through `torchrun` or direct Python process spawning.
- Distributed data samplers and globally reduced loss and accuracy metrics.
- Rank-zero checkpoint, report, log, and plot ownership.
- Portable checkpoints that can be loaded by single-GPU inference.
- Class names sourced from torchvision datasets instead of displaying only numeric indices.
- Training history, dataset sample, prediction grid, confusion matrix, and classification report outputs.

## Requirements

- Python `>=3.14`.
- PyTorch and torchvision.
- CUDA-capable GPUs for DDP or CUDA training.
- `uv` is recommended for environment and dependency management.

Install dependencies with:

```bash
uv sync
```

The EMNIST files are downloaded automatically to `data/` when they are not already available.

## Configuration

The default configuration is `configs/emnist.yaml`.

Important settings include:

```yaml
data:
  train_mode: ddp       # ddp | single
  split: byclass         # byclass, bymerge, balanced, letters, digits, mnist
  batch_size: 128        # Per-process batch size in DDP mode

train:
  epochs: 2
  device: auto           # auto | cpu | cuda | mps

output:
  root: outputs/
```

Command-line arguments override the YAML configuration.

## Training

### Single GPU

Use `--train-mode single` even when the configuration file defaults to DDP:

```bash
uv run python scripts/train.py \
  --config configs/emnist.yaml \
  --train-mode single \
  --device cuda \
  --run-name emnist_single
```

For CPU training:

```bash
uv run python scripts/train.py \
  --config configs/emnist.yaml \
  --train-mode single \
  --device cpu \
  --run-name emnist_cpu
```

### Multi-GPU With `torchrun`

For two GPUs:

```bash
uv run torchrun \
  --standalone \
  --nproc_per_node=2 \
  scripts/train.py \
  --config configs/emnist.yaml \
  --train-mode ddp \
  --device cuda \
  --run-name emnist_ddp
```

Set `--nproc_per_node` to the number of GPUs used by the run.

### Multi-GPU With Direct Python

The training script can spawn one process per GPU directly:

```bash
uv run python scripts/train.py \
  --config configs/emnist.yaml \
  --train-mode ddp \
  --nproc-per-node=2 \
  --device cuda \
  --run-name emnist_ddp
```

In DDP mode, every rank runs all configured epochs over a different data shard. `--batch-size` is the per-GPU batch size, so the effective global batch size is `batch_size * world_size`.

Training logs the active rank, world size, local GPU, available GPU count, epochs per rank, and effective batch size. DDP requires at least two available CUDA devices for multi-GPU execution.

## Inference

Use a portable best checkpoint generated by training. Replace `<best-checkpoint>.pt` with the actual file in the run's `checkpoints/` directory:

```bash
uv run python scripts/inference.py \
  --checkpoint outputs/emnist_single/checkpoints/<best-checkpoint>.pt \
  --image data/inference_images/test_image.png \
  --data-root data/ \
  --split byclass \
  --device cuda
```

CPU inference:

```bash
uv run python scripts/inference.py \
  --checkpoint outputs/emnist_ddp/checkpoints/<best-checkpoint>.pt \
  --image data/inference_images/test_image.png \
  --data-root data/ \
  --split byclass \
  --device cpu
```

The `--split` value must match the split used to train the checkpoint. Inference loads class names from the corresponding torchvision EMNIST dataset and prints the predicted label, confidence, and class probabilities.

## Outputs

Each run is stored under `outputs/<run_name>/`:

```text
outputs/<run_name>/
├── checkpoints/
│   ├── *_best.pt                   # Best validation checkpoint
│   └── *_last.pt                   # Most recent checkpoint
├── logs/
│   └── train.log
├── metrics/
│   ├── history.csv
│   ├── classification_report.json
│   └── confusion_matrix.png
└── plots/
    ├── dataset_samples.png
    ├── training_history.png
    └── test_predictions.png
```

Only rank zero writes shared output files during DDP training. Checkpoints contain unwrapped model weights and can be loaded by the existing single-GPU `Predictor`.

## Useful Overrides

```bash
uv run python scripts/train.py \
  --config configs/emnist.yaml \
  --train-mode single \
  --split balanced \
  --epochs 10 \
  --batch-size 256 \
  --lr 0.0005 \
  --run-name emnist_balanced
```

Available EMNIST splits are `byclass`, `bymerge`, `balanced`, `letters`, `digits`, and `mnist`.
